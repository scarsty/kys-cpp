# 新增实验功能

## MCP stdio

桌面入口支持 `--mcp-stdio`，`McpServer` 保留原 stdout 用于 MCP JSON-RPC，将游戏 stdout 重定向至 stderr，不启动网络服务或后台输入线程。`RunNode::dealEventSelfChilds` 在分发事件前非阻塞轮询 stdin，因此嵌套菜单及 `run(false)` 以实际运行节点为上下文，不依赖绘制栈顶。动画的 `check_event=false` 路径仍提供查询，但不接受控制。

`press_key` 只排入一组按下/松开事件，后续通过原事件树处理，不在绘制栈遍历中直接触发剧情。`RunNode::present` 在 UI 绘制完成、提交窗口前执行按需截图；PNG 由内存编码返回，不写临时文件。所有场景和存档读取在主线程执行，地图坐标来自当前场景而非存档缓存。stdin 关闭时退出绘制栈及当前运行节点；输出断开也会结束本次 MCP 游戏运行。普通启动不启用这些行为。

## 时间系统

`DayNightSystem` 由 `Application` 直接放入全局 RunNode 绘制栈底部，不参与绘制或事件处理，只在 `backRun()` 更新本次运行的昼夜时间。地图与 Paper 战斗共享该系统提供的天空和环境光。

它是常驻根节点，由 `addIntoDrawTop()` 插入而不调用 `run()`，位于所有全屏场景下方。每次执行全局绘制栈的更新时仍会调用它的 `backRun()`，但它不会出现在实际画面中。

时间系统选项为“变化、正午、子夜”，对应 `game.time_mode` 的 0、1、2。固定模式即时使用 12:00 或 00:00 的光照，不推进动态时钟；切回变化时继续此前时刻。未设置新键时兼容 `dynamic_day_night`：旧关闭对应正午，旧开启对应变化。

昼夜时间不写入存档；动态时钟首次初始化时随机选择初始时段。地图与 Paper 战斗共享天空和环境光，固定模式不显示时间标签。

## 主角局部灯光

普通大地图和子场景共用 `Scene::renderLanternScene` 合成主角局部灯光：场景先以白色环境色绘制，再通过带逐顶点颜色的网格统一应用昼夜环境色和暖色径向衰减，避免重复压暗。光圈半径为 8 个 `TILE_W`，中心位于角色脚底上方 3 个 `TILE_H`，跟随平滑行走、独立镜头和地面高度；白天直接合成，不增添灯光绘制。辅助纹理随场景尺寸变化重建，UI 不受影响。径向光圈本身不处理墙面朝向或穿墙遮挡；子场景另有下述方向受光近似，Paper 大地图和战斗保持原效果。

### 子场景墙面局部受光

墙面方向系数按贴图顶点在墙平面上的位置分别计算，不再给整块墙使用同一个系数，减少相邻墙段之间的亮度跳变。当前仍为顶点插值的粗略效果。

普通子场景将 `Scene::isWallTile` 范围内的建筑统一视为平墙，以相邻墙格的连接数量推断沿地图 X 或 Y 的两个主方向；连接数相同时，1410–1436、1816–1849 默认沿 Y，其余沿 X。这是粗略规则，不区分转角、柱体和屋檐。可见面法线分别取 +Y、+X，主角的平滑显示位置决定方向受光系数。墙体顶点预先补偿后续径向灯光，只削弱局部灯光贡献，环境光保留；补偿与径向光均使用顶点插值，因此是近似效果，不处理墙后遮挡。大地图、战斗和 Paper 不变。

## 地图行走与显示插值

普通 `MainScene` 和 `SubScene` 共用 `Scene` 的移动状态、真实时间插值、提交/取消及投影/鼠标反算辅助函数；逻辑人物坐标始终为整数，到达后才提交。游戏选项通过现有 `UIConfig` / `GameUtil` 机制持久化 `game.smooth_walking`：0 原版（禁用）、1 快速 33 ms、2 标准 66 ms（默认）、3 慢速 150 ms。原版仍使用 `walk_speed`（默认 20 ms）和原有起步调度；平滑模式不受该间隔限制，连续迈步保留上一格的时间余量，空闲、菜单和传送清除余量。Paper 大地图和战斗不启用插值。

人物与镜头分别插值：子场景允许 `view` 与 `man` 分离，开始移动时记录独立镜头起点，到达时视野回到人物；缓存 `searth` 地面使用同一镜头偏移并裁剪源/目标矩形。人物显示深度和地面高度随进度变化，其他建筑、事件、装饰仍按格序遮挡。鼠标反算使用当前显示镜头，途中重新寻路从本步终点开始。

入口、子场景经过事件和鼠标末端交互在整数格到达后执行，键盘接管清除鼠标路径。菜单/控制台取消未完成步，停留在已提交格，避免提前触发事件或从菜单恢复后跳步；传送取消旧插值。脚本 `Event::walkFromTo` 的平滑分支逐格驱动共享状态并绘制，期间不分发玩家移动/经过事件；原版保留原脚本调度。`subMapViewFromTo` 仍只移动镜头，`setManViewPosition` 同步人物与镜头并取消旧状态。
