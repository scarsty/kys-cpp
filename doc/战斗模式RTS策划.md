# RTS 小队即时战术模式策划

## 定位与状态

本模式采用固定斜俯视视角，围绕单位选择与即时指挥设计，不以模仿某个具体游戏为目标。目标是在现有即时战斗基础上，增加独立的 RTS 小队战术模式：玩家不再持续操纵一名主角，而是选择友军、下达命令，由单位完成移动和战斗动作。

已创建 `BattleSceneRTS`，继承 `BattleSceneAct`，以复制 `BattleSceneHades` 的声明与实现为改造起点。已接入战斗模式设置中的“RTS”选项（`game.battle_mode=4`），原有模式编号不变。当前已移除直接操纵主角的键鼠与手柄输入，使用经典画法：左键拖框按脚底投影点选择存活友军，松开后仅选中角色显示头顶血条。镜头入场后仅允许按住右键拖动，速度为鼠标位移的两倍；取消自动跟随、死亡切镜、震屏及特写缩放，右键拖动保留已有选择。友军暂由原 AI 自动行动，底部 boss 血条和主角技能操作面板保持隐藏；尚未实现点选、Shift 增减选择、移动和攻击指令。以下其他战术规则为后续规划。

核心体验是少量武侠角色的站位、集火、牵制和武功配合，不是大规模兵海 RTS。首版以 6 名可控友军、6 名同时在场敌人的遭遇战作为验证场景；这是测试规模，不预先定义最终人数上限。

保留现有回合制、半即时、黑帝斯和只狼模式，不改变它们的输入与规则。暂不引入资源采集、建筑、生产、科技树、战争迷雾、联网对战和大规模单位调度。

## 核心战斗流程

当前我方入场原地待命，不主动寻找敌人；受到攻击后仅在射程内还击攻击者，不追击。圈选后右键点击敌人下达指定攻击命令，允许接近并攻击该目标；目标死亡或离场后结束该命令。右键移动超过拖动阈值时仍为拖图，不下攻击命令。

当前 RTS 战斗模拟按原速度的 50% 推进，统一减慢角色移动、动作、攻击特效、冷却和战斗内计时。绘制、鼠标框选、右键拖图和边缘卷屏保持原响应速度，其他战斗模式不受影响。

普通受击或角色死亡不触发全局画面冻结及额外慢动作，角色自身的受击硬直与击退保留。仅战斗结束的最后一击恢复震屏和特写，镜头对准最后倒下的角色，并保留结算停顿与慢动作；结算演出期间停止框选和拖图。

1. 沿用现有战斗入口、地图与选人流程，部署我方队伍。
2. 玩家点选或圈选单位，下达移动或指定目标攻击命令。
3. 单位按命令寻路、接近、选择武功并执行现有动作；冷却、体力、内力、硬直及击退继续生效。
4. 玩家通过重新站位、集火、停止和原地警戒调整局面。
5. 沿用战斗胜负、奖励与退出流程；敌方待出场队列仍计入胜负判断。

首版可保留现有分批增援，测试关卡同时提供固定敌方阵容，避免增援规则干扰基础操作验证。

## 操作方案

已实现边缘卷屏：鼠标停在有效画面边缘 20 个 UI 像素内时持续平移视角，速度为每秒 600 个 UI 像素，斜向速度归一化。框选或右键拖动期间不叠加边缘卷动；窗口失焦、鼠标离开有效画面或战斗结束时停止。镜头仍限制在地图范围内，不自动跟随单位。

首版只支持桌面键鼠与经典画法。鼠标暂定采用左键上下文指令、右键取消选择方式。以下为本模式拟定操作，实施时须检查与现有 UI 的冲突。

| 操作 | 行为 |
|---|---|
| 左键点击友军 | 单选；优先命中屏幕上可见的角色范围 |
| 左键拖动 | 框选存活且可控的友军，以角色脚底投影点判断是否入框 |
| Shift + 点选或框选 | 增减选择，不覆盖其他已选单位 |
| 左键点击地面 | 已选中单位时向目标区域移动，多人自动分配不同落点；未选中时不下令 |
| 左键点击敌人 | 已选中单位时攻击指定目标，所有选中单位接收同一目标 |
| 按住右键拖动 | 快速拖动地图，取消正在进行的框选但保留已选单位；松开右键停止拖动 |
| S | 停止当前命令 |
| H | 原地警戒 |
| 方向键或 WASD | 平移镜头，不再直接控制角色 |
| 滚轮 | 缩放镜头，不再触发攻击或闪身 |
| Space | 镜头回到选中队伍；后续战术暂停另设按键 |

选择框、角色选中圈、目标标记、移动落点和不可达反馈必须可见。UI 点击不穿透战场；没有选中单位时不下令。点击敌人只改变命令，不将敌人加入可控集合。拖动与点击使用位移阈值区分，框选结束不再触发地面移动命令。

首版不保留黑帝斯的鼠标轻击、重击、远程攻击绑定，避免同一次点击既选择又施放技能。手柄、触屏和 Paper 旋转镜头拾取后续单独设计。

## 命令规则

每个可控单位持有自己的命令状态。玩家重新下令默认替换旧命令；命令队列留待后续阶段。

| 命令 | 执行规则 | 完成或失效后的行为 |
|---|---|---|
| 移动 | 前往分配落点，不主动追击途中敌人 | 到达后待命；不可达则提示并结束 |
| 攻击目标 | 保持指定敌人，按武功距离接近并攻击 | 目标死亡、离场或持续不可达时结束并待命 |
| 停止 | 清除命令与自主行走意图 | 留在当前位置附近待命 |
| 原地警戒 | 不主动寻路，仅攻击适合射程内敌人 | 持续生效，直到重新下令 |
| 攻击移动（后续） | 向目的地前进，遇敌交战 | 当前交战结束后继续原路线 |

待命的首版规则为不主动追击，仅在不移动的条件下攻击范围内敌人。原地警戒同样不追击，后续可通过交战姿态扩展待命行为。

命令不能绕过体力、内力、冷却、硬直和死亡判定；停止不清除击退、下落或已经发出的攻击特效。新命令可以先记录，在角色恢复行动能力后执行，避免强制打断动作造成状态错误。

指定目标必须贯穿接近、朝向、发射与追踪逻辑，不能在发招时又被“最近敌人”替换。弹道仍按现有碰撞结算，指定目标不代表必中，也不禁止误中其他敌方单位。

## 移动与队伍协作

- 首版复用现有网格通行判断与距离层寻路，连续物理坐标负责实际移动，不影响主地图的整数坐标规则。
- 群体移动围绕目标分配分散且可通行的落点，保持确定的单位与落点关联，避免每帧重新分配引发来回换位。
- 接近同一目标时，根据近远程需求分配停靠距离，不让所有人挤到目标中心。
- 对重寻路限频；目标明显移动、路径受阻或检测到卡住时才更新，避免所有单位每帧重复搜索。
- 区分静态障碍、友军暂时阻挡和真正不可达。增加到达容差及超时反馈，避免窄门前无限抖动或静默放弃命令。
- 移动意图与击退、闪身等物理效果分开，命令层不直接覆盖外力。

先验证可靠移动，再增加正式编队与复杂避让；不以单位互相穿透作为默认解决方案。

## 武功与策略

首版保留已有武功、攻击特效、碰撞、消耗和伤害体系，由单位自动选择可用攻击。可控友军优先以已装备武功作为候选，避免出现玩家无法预期的技能选择；具体权重与射程判断在实现时验证。

后续按以下顺序扩展：

1. 攻击移动与有限追击：清理沿途敌人，限制单位脱离队伍的距离。
2. 交战姿态：主动、守位、被动；与移动命令的优先级明确区分。
3. 技能自动施放开关与单选单位技能指令，多选技能操作另行设计。
4. 战术暂停（可选扩展）：冻结战斗模拟，仍允许选择、观察和下令；恢复后执行，不消耗暂停期间的冷却或产生追帧突进。
5. 编队、巡逻、护卫、快捷编组及 Shift 命令队列。

首版不直接移植所有 ACT 操作。闪身、道具消耗和范围武功的自动使用需要避免无意义消耗，后续以明确的自动施放策略补齐。

## 镜头与反馈

镜头独立于主角，不因主角死亡强制跳转。支持平移、缩放、回到选中单位，并限制在合理战场区域。首版关闭或显著减弱全局击杀特写、停顿、震屏和慢动作，避免局部交战影响整支队伍指挥。

当前 RTS 模式仅为圈选的存活友军绘制头顶血条，未选中时不显示，底部 boss 血条保持隐藏，保留头像面板。选中角色对应的小状态面板显示绿色边框，取消选择或角色死亡后移除。后续选中面板计划展示人数与当前命令，单选时展示详细状态。指令反馈区分接受、到达、目标失效和不可达。提示应合并或节流，避免多人下令刷屏。

## 技术落地原则

以独立类 `BattleSceneRTS` 为改造起点，目前按整份复制已有即时战斗代码的方式建立基线，暂不重构现有模式。后续在新类中逐步替换输入、命令和 AI，再根据实际重复情况提取共用的模拟、动作和攻击逻辑。新增模式入口时隔离输入，不让 RTS 鼠标指令进入原 ACT 输入分支。

建议的职责边界：

- 选择与输入：屏幕坐标命中、拖框、修饰键和命令生成。
- 单位命令：保存目标与目的地，处理替换、完成、取消和失效。
- 战术决策：由命令决定接近、守位、瞄准和技能选择，敌方继续使用自身 AI。
- 模拟与表现：复用移动碰撞、动作、特效和伤害结算，镜头与 UI 独立更新。

目标引用必须考虑死亡、增援和退出，不因保存失效角色指针而继续操作。是否使用稳定标识或经过验证的引用，由实际角色生命周期决定。

## 分阶段交付与验收

### 第一阶段：最小可玩原型

独立模式入口、经典画法、点选/圈选、左键上下文移动/指定攻击、右键取消选择、停止/原地警戒、独立镜头。

验收场景：

- 6 名友军圈选后移动，分配不同落点，不被原自主 AI 拉去追敌。
- 点击指定敌人后，即使另一个敌人更近，接近与攻击仍尊重原目标。
- 数名单位绕墙、过窄门、集火时不持续互相推挤或来回换位；无法通行时有反馈。
- 目标死亡、单位受击、击退、死亡以及敌方增援不产生失效命令或崩溃。
- 菜单与命令按钮不误触战场，切出窗口不遗留拖框状态。
- 原有各战斗模式的入口、输入与胜负行为不变。

### 第二阶段：战术能力

攻击移动、射程偏好、有限追击、姿态与技能自动施放控制；验证远程单位不持续贴身、队伍不会无限追击。

### 第三阶段：操作深化

战术暂停、编组、命令队列、编队与更多关卡。再评估 Paper、手柄和触屏适配。

每阶段记录单位数、攻击特效数、寻路次数与帧耗时；性能目标须在指定测试机器和固定战场下建立基线，不能仅凭小场景流畅就认定可扩展为大规模 RTS。
