# 效果描述語法設計

## 目標

效果描述不是 YAML 的另一份真相，也不是每個 action 各自拼一段字。完整描述、精簡描述、戰鬥初始化摘要及面板文字都由解析後的 `EffectRule` 產生，並與執行器讀取相同的 payload。

本文件處理四類容易讓字串拼接失控的規則：多動作順序、同時動作、條件分支，以及跨事件狀態機。

## 三層模型

描述管線固定分成三層：

```text
EffectRule / EffectAction payload
        ↓ semantic formatter
EffectDescriptionNode（不含標點與排版）
        ↓ full / compact renderer
localized text
```

semantic formatter 可以讀 enum label 與 payload 數值，但不能接收設定中的自由文字。renderer 只決定詞序、標點、單位及是否省略已由面板標題表達的主詞；它不重新解讀戰鬥語意。

## 描述語意節點

```cpp
struct EffectDescriptionNode;
using EffectDescriptionChild = std::unique_ptr<EffectDescriptionNode>;

struct DescriptionClause
{
    DescriptionSubject subject{};
    DescriptionPredicate predicate{};
    std::vector<DescriptionArgument> arguments;
    std::vector<DescriptionQualifier> qualifiers;
};

struct DescriptionSequence
{
    std::vector<EffectDescriptionChild> steps;
};

struct DescriptionSimultaneous
{
    std::vector<EffectDescriptionChild> actions;
};

struct DescriptionConditional
{
    DescriptionCondition condition{};
    EffectDescriptionChild whenTrue;
    EffectDescriptionChild whenFalse;
};

struct DescriptionForEach
{
    DescriptionTargetSet targets{};
    EffectDescriptionChild body;
};

struct DescriptionStateCycle
{
    EffectDescriptionChild record;
    EffectDescriptionChild consume;
    EffectDescriptionChild reset;
};

struct EffectDescriptionNode
{
    std::variant<
        DescriptionClause,
        DescriptionSequence,
        DescriptionSimultaneous,
        DescriptionConditional,
        DescriptionForEach,
        DescriptionStateCycle> value;
};
```

節點中保存的是 `DamagePercent(25)`、`DurationFrames(90)`、`TargetCount(3)` 等 typed argument，不保存「傷害增加25%」這類完成字串。繁體中文詞彙由 localization table 依 semantic ID 取得。

## 規則文法

概念文法如下：

```ebnf
rule          = trigger, [conditions], body, [limits] ;
body          = action
              | sequence
              | simultaneous
              | conditional
              | state-cycle ;
sequence      = action, { "then", action } ;
simultaneous  = action, { "and", action } ;
conditional   = "if", condition, body, ["else", body] ;
state-cycle   = "record", action, "consume", action, "reset", action ;
action        = subject, predicate, arguments, [qualifiers] ;
limits        = chance | activation-limit | per-cast-limit | stack-limit ;
```

`then` 與 `and` 不是 YAML 字串：由 action 的執行相依關係產生。兩個 action 若讀寫同一中間值，或後者明確讀取前者的結果，使用 `DescriptionSequence`；互不相依且在同一事件結算的 action 使用 `DescriptionSimultaneous`。

## 固定排序

完整描述的資訊順序固定為：

1. 觸發事件。
2. 觸發條件與機率。
3. 目標及選擇順序。
4. 依執行順序排列的動作。
5. 持續時間、疊加／刷新及上限。
6. 每次施放／每目標限制。

精簡描述使用相同順序，只縮短 label 與標點；不能移除會改變戰術判斷的條件、目標、持續、上限或傳播限制。

## 組合規則

### 單一動作

青囊奇術的 semantic node：

```text
Trigger(UltimateCommitted)
Clause(Target=LowestHpAlly,
       Predicate=RestoreHp,
       Arguments=[TargetMaxHpPercent(7)])
```

- 完整：`施放絕招時，為生命比例最低的友軍回復其7%最大生命。`
- 精簡：`絕招·最低生命友軍·回復7%最大生命`

`7` 只來自 `EffectNumber`。

### 同時動作

九陰神功的閃避與暴擊都在同一事件、同一目標、同一持續時間生效：

```text
Simultaneous(
  ModifyAttribute(Evasion, +15%),
  ModifyAttribute(CriticalChance, +25%))
SharedQualifier(Duration=120, Stack=Refresh)
```

- 完整：`施放絕招時，自身閃避率增加15%、暴擊率增加25%，持續120幀；重複施放只刷新時間。`
- 精簡：`絕招·閃避+15%／暴擊+25%·120幀·刷新`

共享 qualifier 只有在 event、selector、duration 與 stack key 都相同時才能提升到組合層；否則各 action 分別描述，避免誤稱共享期限。

### 有順序的多動作

玄冥神掌必須表達先結算、再清除、再重上毒：

```text
Sequence(
  SettleRemainingPoisonDamage(AllEnemies),
  RemoveStatus(AllEnemies, Poison),
  ApplyStatus(AllEnemies, Poison, 10%, 5 ticks))
```

- 完整：`施放絕招時，立即結算所有敵人現有中毒的剩餘傷害，接著清除舊中毒，再施加每次10%傷害、共5次的中毒。`
- 精簡：`絕招·全敵引毒→清毒→重上10%×5`

renderer 不得把 sequence 排序成 action family 的固定順序。

### 條件分支

一氣化三清的每個受益者各自判斷：

```text
ForEach(SelfAndLowestMpAllies, count=3,
  Conditional(
    MpWasFullBeforeCast,
    GrantShield(160),
    RestoreMp(20)))
```

- 完整：`施放絕招時，依序為自身及目前內力最低的兩名友軍回復20點內力；個別受益者施放前若已滿內，改為獲得160點護盾。`
- 精簡：`絕招·自身＋低內2人·回內20；滿內改護盾160`

條件作用範圍由 AST nesting 決定，不能靠逗號位置推斷。

### 跨事件狀態循環

太極拳、太極劍法與柔雲共享一個具名 formatter：

```text
StateCycle(
  Record=RecordMaximum(ActualSkillHpDamage, SincePreviousMatchingUltimate),
  Consume=AddDamageOrShield(RecordedMaximum),
  Reset=AfterConsume,
  Initial=0)
```

太極拳／劍完整描述：`記錄自上次施放本絕招後受到的最大單次招式生命傷害；下次施放時，主彈道附加等量純粹傷害，隨後清空記錄。首次記錄值為0。`

柔雲完整描述：`記錄自上次施放本絕招後受到的最大單次招式生命傷害；下次施放時獲得等量護盾，隨後清空記錄。首次記錄值為0。`

狀態機 formatter 仍由 typed state payload 組成，不接受一段手寫武功說明。共用的 record/reset 子句只能實作一次。

## 觸發與傳播用語

下列差異必須顯示：

| 語意 | 完整用語 | 精簡用語 |
|---|---|---|
| 每根絕招一次 | 施放絕招時 | 絕招 |
| 主彈道命中 | 絕招主彈道命中時 | 主彈命中 |
| 所有合資格彈道 | 本次絕招每次命中時 | 每次命中 |
| 施放全部後代完成 | 本次絕招全部攻擊結算完成後 | 絕招結算 |
| 免費追加、不傳播大招效果 | 不消耗內力，且不再次觸發大招效果 | 免費追加·不觸發大招效果 |
| 同 cast 每目標一次 | 每次施放對同一目標最多觸發一次 | 每施放每目標1次 |

描述使用[施放來源與結算生命週期設計](施放來源與結算生命週期設計.md)的 propagation enum；不能由 `mainProjectile` 等單一 bool 猜測。

## 數值、單位與取整

- 比例一律顯示 `%`；幀數顯示「幀」；棋格距離顯示「格」。
- `EffectNumber` 若同時有比例與固定值，依實際算式顯示，例如 `3%最大生命＋60生命`。
- `星級×100` 顯示公式，不展開成三組手寫數字；如果 UI 有確定星級，可由同一 payload 額外顯示計算結果。
- 只有會影響玩家預期的取整規則才在完整 tooltip 補充；精簡描述可省略，但測試仍須涵蓋。
- `0` 若有語意必須顯示，例如太極首次記錄值；不能因 compact renderer 的「省略零值」規則消失。

## 完整與精簡 renderer

兩個 renderer 共用：

- 同一 semantic AST；
- 同一 action formatter registry；
- 同一 enum localization；
- 同一數值與單位 formatter；
- 同一 qualifier 去重邏輯。

差別僅限：

| 項目 | 完整 | 精簡 |
|---|---|---|
| 句法 | 完整主詞、動詞與連接詞 | 固定短標籤與 `·／→` |
| 標點 | 句號、分號、逗號 | 中點、斜線、箭頭 |
| 已知上下文 | 保留事件主詞 | 面板已標示來源時可省略來源名 |
| 次要說明 | 顯示取整、死亡結算等 | 可折疊，但不可省略目標與限制 |

不得各自維護 action switch。新增 action variant 時，只新增一個 semantic formatter；兩個 renderer 必須自然支援其輸出節點。

## 禁止的 escape hatch

以下欄位不進入 schema：

- `說明`、`描述`、`tooltip`；
- `完整說明覆寫`、`精簡說明覆寫`；
- action 內的 `前綴`、`後綴`、`自訂文字`。

只有不含機制數值的 localization label 可由內容指定，例如狀態顯示名「寒毒」。若新機制無法描述，應補 semantic node 或 formatter，不能用自由文字繞過。

## 測試契約

### 覆蓋與 round-trip

每個可載入的 action／condition／selector variant 都必須：

1. 能產生非空 semantic AST。
2. 能產生完整與精簡文字。
3. 兩種文字都不含未解析 token。
4. 描述中出現正確目標、事件及限制。

### 可見數值突變測試

為每個 payload 的玩家可見數值欄位建立 mutation test：複製規則，只改一個值，完整描述與精簡描述都必須改變。欄位清單由 schema reflection／variant visitor 產生，不能人工漏列。

反向測試也要成立：只改 runtime ID、來源容器索引等不可見欄位，描述不得改變。

### Golden 的用途

Golden snapshot 用來檢查繁體中文語序與排版，不用來證明數值同步。數值同步由 mutation test 證明；執行與解析等價由[效果設定差分遷移設計](效果設定差分遷移設計.md)的 canonical 比較證明。

至少固定以下 compound golden：五虎斷門刀、玄冥神掌、一氣化三清、太極拳、乾坤大挪移、夫妻刀法、小無相功、斗轉星移及葵花神功。
