# 施放來源與結算生命週期設計

## 問題

目前 `sharedHitGroupId` 只表示一組攻擊是否已命中同一目標，`spawnedFromAttackId` 只表示直接父攻擊；兩者都不能回答：

- 這枚彈道屬於哪一次根施放；
- 側翼、延遲、追蹤、反彈與免費追加是否可觸發大招規則；
- 哪些後代仍未結算；
- 三分、鐵掌等「本次絕招完成後」何時只能觸發一次。

本設計新增一份不可拆散的 provenance value 與一個中央生命週期 tracker，不在每個 spawn site 個別傳 `castId` bool。

## ID 與 provenance

```cpp
using BattleCastId = StrongId<struct BattleCastIdTag>;
using BattleAttackId = StrongId<struct BattleAttackIdTag>;

enum class CastOriginKind
{
    Normal,
    Ultimate,
    FreeRepeat,
    CopiedAttack,
    BorrowedEffect,
    Echo,
    RescueCounter,
};

enum class CastPropagationPolicy
{
    SourceRules,
    SourceHitRulesOnly,
    SuppressUltimateRules,
    BorrowedUltimateRules,
    NoEffectRules,
};

struct BattleCastProvenance
{
    BattleCastId rootCastId{};
    BattleCastId castId{};
    std::optional<BattleCastId> parentCastId;
    int sourceUnitId{};
    int magicId{};
    bool ultimate = false;
    CastOriginKind origin{};
    CastPropagationPolicy propagation{};
};

struct BattleAttackProvenance
{
    BattleCastProvenance cast{};
    BattleAttackId attackId{};
    std::optional<BattleAttackId> parentAttackId;
    int attackOrdinal{};
    bool rootAttack = false;
    bool mainProjectile = true;
    SharedHitGroupId sharedHitGroupId{};
};
```

`BattleAttackSpawnRequest` 在尚未分配 attack ID 時攜帶 `BattlePendingAttackProvenance`；`BattleAttackState::spawn` 分配 ID 後一次轉成完整 `BattleAttackProvenance`。`BattleAttackInstance` 與 `BattleAttackEvent` 都保存／複製同一 value，不再平行保存 `ultimate`、`mainProjectile`、`spawnedFromAttackId`、`skillEffectRef` 等可能互相矛盾的來源欄位。

`skillId`、傷害、位置與速度仍是攻擊 payload，不屬於 provenance。`skillEffectRef` 被來源綁定與 propagation 取代。

## 根施放、子施放與衍生攻擊

- 玩家／AI 正常提交一次武功時建立 `rootCastId == castId` 的根施放。
- 同一次施放產生的側翼、扇形、延遲落點、追蹤 follow-up 及反彈，只建立衍生攻擊，沿用同一 `castId`。
- 玉女、小無相等真正重新執行另一份武功攻擊定義時建立 child cast：新 `castId`、相同 `rootCastId`、填入 `parentCastId`。
- 斗轉借用規則不建立被偷武功的攻擊 child cast；它在目前 cast 加入暫時來源綁定。
- 非武功反擊（例如救援普攻）若不是由一個現存 cast 派生，建立自己的普通根 cast，不能使用空 cast ID。

`rootCastId` 用於整棵施放樹的生命週期與 replay 關聯；`castId` 用於「每次施放」「每目標一次」及該武功自己的聚合值。父 cast 的 `CastSettled` 是否等待 child cast，由 child 的 work 是否掛在同一 root tracker 決定；本設計一律等待，避免父事件早於免費追加攻擊。

## 傳播政策

傳播政策只決定效果規則的可見範圍；回內、傷害倍率等攻擊經濟由攻擊 payload 的其他 typed policy 決定，不塞入 propagation enum。

| 來源 | cast／attack 關係 | propagation | 提交規則 | 來源大招命中規則 | 借用規則 | 可再生成複製／殘影 |
|---|---|---|---|---|---|---|
| 正常絕招根攻擊 | 根 cast／根 attack | `SourceRules` | 是，一次 | 是，依事件與主彈條件 | 否 | 是 |
| 側翼／扇形主彈 | 同 cast／衍生 attack | `SourceHitRulesOnly` | 否 | 是 | 繼承 | 依規則條件 |
| 延遲落點／追蹤 follow-up | 同 cast／衍生 attack | `SourceHitRulesOnly` | 否 | 依 `mainProjectile` | 繼承 | 依規則條件 |
| 反彈鏈 | 同 cast／衍生 attack | `SourceHitRulesOnly` | 否 | 沿用父 attack 的主彈資格 | 繼承 | 否，防止每跳擴張 |
| 玉女免費重施 | child cast／根 attack | `SuppressUltimateRules` | 否 | 否 | 否 | 否 |
| 小無相複製武功 | child cast／根 attack | `SuppressUltimateRules` | 只評估小無相本身已在父 cast 完成的提交規則 | 不使用被複製武功的大招規則 | 否 | 否 |
| 斗轉偷取效果 | 原 cast／原攻擊 | `BorrowedUltimateRules` | 被選規則按暫時來源評估 | 是，但不借其武功基礎攻擊 | 是 | 否；排除複製 action |
| 葵花殘影 | 同 cast／衍生 attack | `SuppressUltimateRules` | 否 | 否 | 否 | 否 |
| 救援反擊 | 獨立普通根 cast | `NoEffectRules` 或既有明定規則 | 依既有行為 | 否 | 否 | 否 |

每個表格列都要有正向與負向測試。不得在特定武功 handler 裡另做 `if (magicId == ...)` 修補傳播。

## 攻擊序號與主彈資格

`attackOrdinal` 在同一 cast 內按建立順序單調遞增，建立 request 時分配，不能等真正 spawn 才分配；如此延遲攻擊不會因排程改變序號。太嶽第三道等規則用 ordinal／具名 pattern index，不讀 frame 或 vector index。

`mainProjectile` 是規則資格，不表示「第一枚」。一陽指、六脈與五虎可讓多枚攻擊都具主彈資格；`rootAttack` 仍只有武功定義的初始攻擊。提交事件只看 cast，不看 main projectile，避免多主彈重複觸發。

## 中央 outstanding-work tracker

```cpp
enum class CastWorkKind
{
    CommitBarrier,
    QueuedAttack,
    LiveAttack,
    ChildCast,
    DelayedEffectCommand,
};

struct BattleCastRuntime
{
    BattleCastProvenance provenance{};
    int outstandingWork{};
    CastAggregate aggregate{};
    bool continuationDispatched = false;
    bool settlementQueued = false;
};
```

`BattleCastLifecycle` 由 `BattleRuntimeState` 持有，提供唯一 API：

```cpp
CastWorkToken beginRootCast(...);
CastWorkToken reserveAttack(BattleCastId castId, ...);
void transferToLiveAttack(CastWorkToken token, BattleAttackId attackId);
CastWorkToken beginChildCast(BattleCastId parentCastId, ...);
void completeWork(CastWorkToken token, CastWorkResult result);
std::vector<BattleCastLifecycleEvent> drainReadyEvents();
```

每份 work 都有唯一 token 與狀態轉移。queue → live 是 token transfer，不是先減再加；因此任何幀邊界都不會暫時得到 0 而誤發 settled。

### 註冊規則

1. 根 cast 建立時先持有 `CommitBarrier`。
2. 任何同步、延遲或 next-frame attack 在放入外部可見容器前先 `reserveAttack`。
3. commit 過程確認不再生成初始子工作後才完成 `CommitBarrier`。
4. 反彈在 `BattleAttackState::tick` 內建立時，先為後代保留 token，再讓後代進入 attacks／events。
5. child cast 在父 action 執行時先向同一 root 登記，再提交 child request。
6. effect command 若會跨幀生成屬於本 cast 的攻擊，必須持有 `DelayedEffectCommand`；DOT、限時狀態與區域預設不讓 cast 保持未結算，除非該機制規格明寫屬於 cast 結算。

### 完成規則

`Hit` 不等於 attack 完成，因為貫穿彈可多次命中，反彈也可在命中後產生後代。只有 attack state 從 live container 移除時完成 token，並記錄唯一原因：

```cpp
enum class AttackFinishReason
{
    SpentOnHit,
    Expired,
    TargetLost,
    ProjectileCancelled,
    ChainEnded,
    NoBounceTarget,
    ExplicitlyCancelled,
};
```

終止 event 與 token 完成由同一個 `finishAttack` 入口產生。不能由 frame runner 看見 `Expired` 後再猜要不要 decrement。debug build 對重複完成、未知 token、負 outstanding count 直接 assert。

## `CastContinuation` 與 `CastSettled` 事件

玉女需要「正常絕招攻擊完成後」建立一次 child cast；鐵掌則要在所有合法後代都完成後才讀取最終聚合值。若兩者共用一個可重複進入的 `CastSettled`，新增 child work 後會讓結算 handler 執行兩次。因此生命週期分成兩個只發一次的事件：

- `CastContinuation`：本 cast 第一輪 work 歸零時發出，只有此事件可建立新的 tracked work；玉女在這裡判定免費重施。每個 cast 永久只 dispatch 一次。
- `CastSettled`：continuation 已 dispatch，且它產生的 child cast／攻擊也全部完成後發出；只允許即時資源、狀態、傷害與聚合讀取，不允許再建立 tracked work。

事件不能在 decrement 呼叫中立即 dispatch，避免 handler 重入。child cast 自己完成 `CastSettled` 後，才完成父 cast 持有的 `ChildCast` token，所以父事件天然晚於子事件。

每幀順序：

1. attack tick／hit resolution 可登記後代及累積 `CastAggregate`。
2. 本幀所有 damage transaction 與死亡連鎖完成，將最終生命傷害寫回 aggregate。
3. work 第一次歸零且尚未 continuation 時，frame runner dispatch `CastContinuation`，隨即永久標記；handler 可以先保留 token 再建立 child work。
4. continuation 沒有建立 work，或其所有後代稍後完成時，tracker queue `CastSettled`。
5. `BattleEffectSystem` 執行 final settled 規則，例如鐵掌護盾、三分不同目標判定；validator 禁止這些規則建立 attack／child cast。
6. settlement 成功 dispatch 後永久標記 settled；每個 cast 的 continuation 與 settlement 各最多一次。

`CastAggregate` 至少保存：不同命中目標集合、最高單次實際生命傷害、總實際生命傷害及每 attack ordinal 的結果。aggregate 以 `castId` 為 scope；child cast 有自己的 aggregate，父 cast 只等待 child 結束，不自動合併其傷害／目標。未來若有規則需要整棵 `rootCastId` 聚合，必須新增明確 scope，不能暗中改變現有父值。集合迭代一律按 unit ID，不依 hash 順序。

## 邊界情況

| 情況 | 契約 |
|---|---|
| 施法者在彈道飛行中死亡 | 不自動取消既有攻擊；沿用現有攻擊存活規則。來源 snapshot 由 provenance 提供，不能解參考死亡單位指標 |
| 施法者死亡且既有機制取消攻擊 | 每枚攻擊以 `ExplicitlyCancelled` 完成，最後才 settled |
| 追蹤目標死亡／消失 | 若不能重選，`TargetLost` 完成；能重選則 token 繼續 |
| 彈道互消 | 兩邊各自只完成一次，先登記任何取消衍生命令再完成來源 token |
| 貫穿命中 | 每次命中更新 aggregate，但保留 token 至 expiry／其他終止 |
| 反彈無下一目標 | 父 attack 以既有終止原因完成，不建立空後代 token |
| 延遲 request 在施法者死亡後到期 | 依原本 spawn 規則生成或取消；兩條路都必須完成原 token |
| child cast 沒有合法目標 | child commit barrier 以取消完成，父 root 仍可正常 settled |
| 戰鬥結束 | 先以明確 battle-ended reason 取消所有 work，再產生或捨棄 settlement；策略固定並納入 digest test |

## 現有建立／複製點稽核

實作時逐一改成接受／複製完整 provenance，並為每點加 lineage test：

| 檔案／位置 | 現況 | 要求 |
|---|---|---|
| `BattleCastSystem::makeBaseRequest` | 根攻擊 | 建立 root cast 與第一個 attack token |
| `BattleCastSystem` 額外彈道 | 複製 prototype | 同 cast、新 ordinal、指定 main qualification |
| `BattleCastSystem` tracking spread | 複製／改目標 | 保留 lineage 與 shared-hit 政策 |
| `BattleCastSystem` `DualWieldFollowUp` | 延遲攻擊 | request 入 queue 前保留 token |
| `BattleAttackSystem::makeBounceAttack` | clone live instance | parentAttackId 指向來源；建立後代 token 後才公開 |
| `BattleHitResolver` nearby tracking | 從 event 重建 | 不可遺失 cast、parent attack、propagation |
| `BattleHitResolver` area follow-up | 從零建立 | 必須由命令帶入 provenance，不可猜 attacker 當新根 |
| `BattleCore` rescue counterattack | next-frame request | 明確建立獨立普通 cast 與 policy |
| `BattleCore` spiral bleed | scripted projectile | 明確決定屬於來源 cast 或獨立 effect cast |
| `BattleRuntimeQueues` | 延遲／next-frame | queue item 擁有 work token，清空／取消時也完成 |

完成遷移後，以 repository 搜尋確認攻擊資料不再平行攜帶已被 provenance 收納的舊欄位。

## 測試矩陣

最低測試集合：

- 單彈命中、未命中 expiry、target lost、projectile cancel。
- 貫穿多目標，只 settled 一次且 aggregate 完整。
- bounce 0／1／多跳，最後一跳完成前不 settled。
- delayed／next-frame request，queue 期間不 settled。
- 一陽指／六脈多主彈：提交一次，命中規則按實際主彈觸發。
- 玉女、小無相、斗轉、葵花各自的 truth-table 正負斷言。
- 施法者死亡、child 無目標、戰鬥提前結束。
- fixed-seed 下 attack ordinal、random draw、settled frame、aggregate 與 GUI／headless digest 一致。
