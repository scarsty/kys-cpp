# 智將五人門檻：額外出戰名額實作計畫

本文件記錄智將五人門檻加員的規則、互動、程式修改範圍與驗收條件。2026-10-24 已依本計畫完成核心、整備互動、地圖與各戰鬥入口的實作；驗證結果記錄於文件末尾。

## 已確認的決策

- 智將五人門檻新增「出戰上限 +1」，保留目前該門檻的屬性加成、免費刷新與戰場選擇。
- 等級提供的出戰上限仍最多為 10；啟動智將加成後最多出戰 11 名實體棋子。
- 不需要舊存檔或舊重播相容，也不製作十格轉十一格的遷移工具。
- 戰役敵軍維持既有關卡配置，允許我方多出一名棋子；不因我方啟動智將而補上一名敵軍。
- 更換裝備、轉移羈絆成員資格及合成後的裝備繼承，都納入可能使出戰加成失效的情境，不能因目前沒有賦予智將資格的裝備而忽略。
- 加成失效時保留玩家操作後的陣容，由玩家調整；不自動挑選棋子下陣或出售。

## 1. 容量與準備完成條件

將以下概念分開，避免一個常數同時代表等級上限、實際可出戰人數及畫面卡片數：

| 概念 | 規則 |
| --- | --- |
| 等級出戰上限 | 沿用現有等級規則，最多 10 名 |
| 羈絆出戰加成 | 智將五人門檻啟動時 +1；更多智將不再增加名額 |
| 實際出戰上限 | 等級出戰上限 + 目前啟動的加成 |
| 陣形位置數 | 固定 11 格，用於保存戰場站位 |
| 候補容量 | 沿用難度平衡設定，目前三種難度皆為 10 |
| 超出人數 | max(0, 出戰人數 - 實際出戰上限) |
| 出戰準備完成 | 至少有一名出戰棋子，且沒有超出人數；另保留各入口既有條件 |

容量加成使用既有羈絆解析器，保留不同角色計數、裝備成員資格及合縱的有效點數規則。五人門檻是羈絆門檻，不強制等於五名實體成員。例如選擇智將的合縱可由四名實體成員加一點啟動。

額外名額屬於整個隊伍，不綁定某一名棋子或第十一格。小隊也可以使用第十一格；合法性取決於出戰總數。選圖必須支援實際使用的最高位置索引，不能只看棋子總數。

戰鬥開始後使用已準備好的陣容；戰中陣亡不重新計算管理階段的出戰上限。真武分身不計入管理階段的出戰人數，也不提供額外出戰名額。

### 操作結果驗證

所有可能改變羈絆貢獻的操作，都計算完整操作前後的容量與人數：部署、替換、出售、裝備指派或卸除、購買與連鎖合成，以及獎勵升星。

- 新增出戰棋子時，必須符合操作完成後的上限。允許新上陣的第五名智將啟動自己需要的額外空間，例如基本上限四名時，由 4/4 成為 5/5。
- 操作沒有增加出戰人數，但因容量降低而超員時，允許完成並進入待調整狀態。例如替換或合成後由 11/11 成為 11/10。
- 已超員時仍可整理、出售、裝備、合成及使用商店；不能藉由新增部署進一步超員。操作後的候補容量與十一格實體限制仍須成立。
- 移動裝備等複合操作，以完成後的狀態判定。例如在兩名出戰棋子間轉移成員資格，不因中途先卸除裝備而短暫宣告失效。
- 陣形結構有效與出戰準備完成分開檢查。11/10 可以是完整、可保存的陣形，但不能開戰。

## 2. 加成失效的互動

以下以等級出戰上限十名為例：

| 操作 | 結果 | 互動 |
| --- | --- | --- |
| 智將加成有效時再上一名棋子 | 10/11 → 11/11 | 一般上陣 |
| 第五名智將下陣，候補有空位 | 11/11 → 10/10 | 只移動指定棋子，其他人保留 |
| 出售第五名智將 | 11/11 → 10/10 | 只出售指定棋子，其他人保留 |
| 以非智將替換關鍵成員 | 11/11 → 11/10 | 完成替換，完整顯示陣容並要求調整 |
| 裝備變更或合成繼承使加成失效 | 11/11 → 11/10 | 完成操作，使用相同的超員處理 |
| 替換回能恢復門檻的棋子 | 11/10 → 11/11 | 立即解除超員提示 |
| 超員時撤回一名棋子，候補有空位 | 11/10 → 10/10 | 立即恢復可出戰 |
| 超員且候補已滿時嘗試下陣 | 不變 | 說明候補限制，保留替換、合成、出售等修復途徑 |
| 升級增加基本容量 | 例如 10/9 → 10/10 | 立即解除超員提示 |

### 持續顯示超員狀態

出戰區顯示 `出戰 11/10 · 超出 1 名`，並在開戰操作附近持續顯示：

> 智將出戰加成已失效。恢復羈絆或減少出戰人數後即可開戰。

文字由實際加成來源與有效點數產生，不能一律聲稱「第五名離場」。所有出戰棋子仍可見、可選取；不指定其中某一名為必須撤回的「額外棋子」。

主線、遠征及 PvP 的開戰控制都說明不可用原因；鍵盤捷徑與 CLI/MCP 也受同一核心規則約束。不能只靠數秒後消失的通知，或只在 GUI 停用按鈕。

### 候補滿員

一對一替換的候補人數不變，必須可以執行。若已持有 21 名棋子，而加成消失後只能容納 10 名出戰與目前設定的 10 名候補，則需要恢復加成、合成或出售來減少人數；不額外提供隱藏儲存空間。

候補上限來自平衡設定。上述 21 名只是目前設定的例子，程式與提示必須使用實際容量計算。

## 3. 候補與出戰棋子的直接替換

在候補棋子的檢視器加入可直接使用的「替換出戰」操作：

1. 選取候補棋子，按「替換出戰」。
2. 保留完整陣容，明確顯示正在選擇替換對象。
3. 滑鼠懸停預覽；點擊或觸控固定出戰目標。
4. 同一檢視器顯示換上、換下角色，以及羈絆點數、容量與超員人數的變化。
5. 在檢視器確認，整筆交易一次完成；取消或 Esc 不改動陣容。

預覽例：`王語嫣上陣 ↔ 某棋子下陣`、`智將 4 → 5 · 出戰上限 10 → 11`。若合縱提供加點，應呈現有效點數與其來源。

替換使加成失效時，確認前顯示 `替換後超出 1 名，需調整後才能開戰`。

換入棋子繼承換出棋子的戰場位置；其他棋子保留位置。沿用既有單擊／雙擊移動偏好，但替換模式必須獨佔目標選擇輸入，避免選取目標同時觸發一般上／下陣。保留穩定 ID、鍵盤焦點及既有連點吞入行為。

## 4. 購買、合成與預覽共用同一結果

將 `BuyShopSlot` 定義為一次確定性的核心交易：

`購買 → 全部合成與裝備繼承 → 自動放置 → 最終容量與候補檢查 → 提交`

- 最終結果可合法上陣時自動上陣，否則留在可容納的候補。
- 候補滿員時，若最終可直接上陣或經合成騰出空間，仍可購買；不先要求中途一定有候補空位。
- 新棋子可啟動智將而取得自身需要的名額，判定使用放置後的完整陣容。
- 合成本身使原有出戰陣容失去加成，可以完成並顯示超員；自動上陣不能再製造超員。
- 購買不自動替換或出售其他棋子。
- 最終沒有合法存放位置時，整筆操作失敗，不扣金幣、不消耗商店格、不部分修改裝備或陣形。
- 回傳連鎖合成後仍存在的最終棋子 ID，供 GUI 選取、動畫及提示使用；不能假定最初購入的 ID 仍存在。
- GUI 移除購買後再額外送一次部署操作的流程。GUI、CLI/MCP 及新重播都執行同一筆核心交易。

商店預覽、購買資格判定與實際提交共用這套結果計算。`queryChessShopSlot` 不再僅於複製狀態呼叫 `grantPiece` 並留在候補，否則無法正確預覽自動上陣後的智將門檻。

裝備與合成測試必須包含這種情境：出戰棋子的裝備提供關鍵成員資格，與候補複本合成後，升星棋子仍出戰，但依現有較高層級優先規則繼承另一件裝備，原成員裝備回到庫存，使容量由 11 降為 10。

## 5. 整備畫面

遵循 [UI 設計語言](ui-design-language.md)，維持 1280×720 固定邏輯畫布、共用樣式與右側檢視器。

- 一般最多十名時保留既有五欄配置。
- 容量或實際出戰人數達十一名時，使用六欄兩排，第一排六名、第二排五名。未使用的第十二個排版位置不表示可取得第十二個名額。
- 11/10 時維持十一名排版，不能以目前上限截斷可見名單。
- 調整肖像尺寸及卡片內容以保留姓名、星級、雙裝備與操作熱區的可讀性，不依實體視窗大小另設版型。
- 顯示 `出戰 10/11` 及 `智將 +1` 來源提示。點擊、觸控或鍵盤選取可查看等級容量與羈絆加成明細。
- 失效提示持續存在；容量恢復或減員完成後立即更新。
- 卡片移動沿用既有動畫並保存選取。合成後改選最終存活 ID。
- 下一格鎖定提示指出真正取得方式：可升級時連到升級資訊；滿級且缺智將加成時連到相關羈絆條件。不能永遠顯示「升級解鎖」。
- 購買經驗預覽在升級前後都納入相同陣容的羈絆加成，避免拿目前總容量與下一級基本容量比較。

### 戰役敵軍

戰役沿用關卡表的實體敵軍數量，允許玩家因智將多出一名，不補齊第十一名敵軍。只有沒有敵軍表的後備流程才會依我方部署數產生敵軍；需分別驗證這兩條路徑。

目前戰役敵軍分身使用未被實體敵軍佔用的敵軍站位，與我方獨立保留三格的規則不同。敵軍滿員時可能沒有分身落點；我方的上述審核不能宣稱已保證敵軍分身容量。

在 `ChessBattleMapCatalogEntry` 加入敵軍分身的補充落點，由 `BattleSetupFactory` 依下列順序提供候選：先沿用目前未被實體敵軍使用的敵軍站位，再接上地圖目錄中的補充落點。既有落點足夠時保留原位置；不足時才使用補充位置，避免為了解決滿員情境而搬動所有既有分身。

九張正常遊戲地圖皆使用審核表明定的三個補充落點，保證敵軍在目錄容量滿員時仍能生成三個分身。補充位置不得佔用我方位置、分身位置或敵軍可能使用的實體起點。原始地圖由 `ChessContentLoader` 從 `resource/war.sta` 讀入，新增位置保存在地圖目錄，不修改舊二進位資料格式。明確指定原始地圖的獨立工具保留自身條件，不作為正常遊戲的選圖後備。

這不增加實體敵軍數。恢復原先因缺落點而未生成的敵軍分身，須單獨記錄這項行為變更；本次不追加實戰難度驗證。

### 選圖與失敗處理

- 依實際使用的最高陣形索引及敵軍需求選擇真正可容納的地圖。共用需求計算，沿用 `requiredFormationSlots` 的最高使用索引語意，不在驗證器與規劃器各寫一份不同的容量規則。
- 主線與遠征只從已審核的九張目錄地圖中選擇，移除「最佳但放不下」精選分支，以及整段掃描原始 `content.battleMaps()` 的後備流程。原始資料只有六個我方起點，不能作為十一格的替代；保留十面埋伏停用及 PvP 專用的排除規則。現在敵人表最多十人，九張皆可用；十二人遠征可用 17、54、56、80，無須後備地圖。
- `PrepareBattle` 與 `StartChallenge` 在 `ChessGameSession::validateAction` 執行不耗用 RNG 的預先檢查：先檢查陣容與容量，再依出戰位置及已知敵軍數量查詢可用地圖。戰役使用敵軍表或既有無表人數規則，遠征使用挑戰定義；不為了查容量先抽選敵方角色或裝備。
- 無適合地圖時，入口直接回傳明確錯誤並停留整備。因正式規劃尚未開始，不會消耗敵軍、裝備、選圖或戰鬥種子的 RNG；不新增事後回滾流程。預先檢查與正式規劃共用需求與候選計算；通過檢查後仍無地圖屬於內部不變條件錯誤。
- 主線與遠征的 `StartBattle` 必須已有可容納凍結陣容的已選地圖；不能再因 `mapCandidates.empty()` 就放行。`ChooseMap`、存檔還原與 `BattleSetupFactory` 使用一致語意，避免進入沒有合法地圖又無法繼續的戰前階段。獨立戰鬥原有的無地圖模擬用途另外保留明確條件，不把它當成主線選圖失敗的成功結果。
- 驗證實體棋子與分身落點的邊界、可行走性及互不重複，不能以佔用分身位置換取第十一名實體棋子的空間。

核心觀察提供基本容量、加成來源、總容量、目前出戰數、超出人數與部署準備錯誤原因；這些值由同一計算推導，不在 UI 另外維護一份可失同步的容量狀態。

合法動作描述必須允許客戶端表達「新陣容自行啟動容量」的部署選擇，不能以舊陣容的上限先截斷可提交人數。最終是否合法由共同的結果驗證決定。

### 存檔與重播

- 新格式固定十一格，允許舊格式直接不相容；不保留十格分支或舊購買語意。
- 新存檔、新重播與驗證器使用完全相同的交易規則及事件。
- 一般整備存檔允許保存、載入 11/10 等待調整狀態；載入後保留全部棋子並顯示原因。
- 已準備戰鬥的存檔必須符合其凍結陣容及地圖需求。
- PvP 匯入與本地出戰都檢查部署準備條件。超員使用明確錯誤，不假稱為陣形結構毀損。

### 戰前與戰後畫面

目前戰前總覽只列實體陣容，十一名仍在既有十三列界限內。戰後報告沿用既有列表呈現實體與分身；核心測試涵蓋我方十四名及 PvP 雙方各十四名，不增加遊戲內人工檢查作為交付條件。

## 8. 實作順序
